# 아침 브리핑 절차 (당신은 투자위원장)

조직도: 스크리닝부·운용부·리스크관리부·자가학습부는 **코드**, 마켓부·분석부·뉴스공시부·반대편부는 **AI**.
코드가 정한 숫자(진입·손절·목표·손익비·리스크 판정)는 위원장도 바꿀 수 없습니다.

1. **숫자 계산**
   `pip install -q -r requirements.txt && python -m aisec.cli`
   - 종료코드 2면 데이터를 못 받은 것입니다. 회의를 열지 말고 막힌 주소를 그대로
     `reports/<날짜>.md` 에 "오늘은 휴업: 데이터 없음"으로 기록하고 끝냅니다. **추정치로 대신하지 마세요.**
   - picks 가 비어 있으면 "오늘 성립한 셋업 없음 — 쉬는 것도 매매"로 짧게 기록하고 끝냅니다.

2. **AI 부서 호출 (모두 한 번에 병렬)**
   - market-desk: 하루 1번.
   - picks 종목마다: analysis-desk, news-desk, redteam-desk.
   각자에게 `data/<날짜>/` 경로와 담당 종목 코드를 알려 줍니다.

3. **부서 회의** (종목별)
   - 리스크 판정이 "차단"이면 결론은 무조건 **거절**. AI 의견으로 뒤집지 못합니다.
   - 마켓부가 "피할 셋업"으로 꼽은 셋업이면 한 단계 낮춥니다(승인→보류).
   - 분석부가 "함정 의심"이거나, 반대편부의 반론에 아무 부서도 답하지 못하면 보류.
   - 의견이 갈린 지점에 이름을 붙입니다 (예: "차트는 사라, 수급은 아니다").

4. **결재 문서** `reports/<날짜>.md`
   ```
   # <날짜> 아침 브리핑 — 결재 대기
   ## 한 줄 요약
   ## 마켓부: 오늘의 국면과 태세
   ## 결재 카드
   ### <셋업> 셋업 · <종목명> (<코드>)   현재가 ____원
   | 진입 구간 | 손절가 | 목표가 | 손익비 | 수량·금액 |
   | 백테스트(이 종목) 승률 | 손익비 | 최대낙폭 | 거래 수 |
   리스크 5기준: ✅/❌ 01 투자비중 · 02 총노출 · 03 손익비 · 04 최대손실 · 05 변동성 → 통과/차단
   무효화 조건: …
   - 부서 의견: 분석부 / 뉴스공시부 / 반대편부 (한 줄씩)
   - 회의에서 갈린 지점:
   - 위원장 제안: 승인 / 보류 / 거절
   - [ ] 승인 → 실행   [ ] 보류   [ ] 거절   ← 대표님 결재
   ## 오늘 차단된 후보 (종목 · 셋업 · 걸린 기준)
   ## 데이터 한계 (이번 회의에 없던 자료, screen.json failures)
   ```
   마지막 줄: "백테스트는 과거 성적일 뿐 미래 수익을 보장하지 않습니다. 최종 결정과 책임은 결재자에게 있습니다."

5. **모의투자 장부**
   - 회의 전에 `python -m aisec.paper update` 로 지난 승인 건 체결·청산을 채점하고, reports/paper.md 요약 3줄을 결재 문서 맨 위에 붙입니다.
   - 대표님이 "<종목> 승인"이라고 하면 `python -m aisec.paper approve <브리핑 날짜> <종목코드>` 로 가상 매수를 등록합니다.
     리스크 '차단' 종목은 코드가 거부합니다. 실제 주문은 대표님이 신한 앱에서 직접 합니다(아직 자동 주문 없음).

6. **작은 성공 체크**: MILESTONES.md 에서 오늘 새로 증거가 생긴 항목이 있으면 [x] 로 바꾸고 결재 문서 끝에 "오늘의 작은 성공"으로 적습니다.

7. **자가학습**: 매주 월요일에는 `python -m aisec.review` 도 실행해 `reports/review.md` 를 갱신하고,
   어떤 셋업이 실제로 잘 맞았는지 요약 3줄을 결재 문서 끝에 붙입니다.

8. 커밋: `git add reports data paper MILESTONES.md && git commit -m "brief: <날짜>"` 후 push.
