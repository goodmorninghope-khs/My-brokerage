# 아침 브리핑 절차 (당신은 투자위원장)

조직도: 스크리닝부·운용부·리스크관리부·자가학습부는 **코드**, 마켓부·분석부·뉴스공시부·반대편부는 **AI**.
코드가 정한 숫자(진입·손절·목표·손익비·리스크 판정)는 위원장도 바꿀 수 없습니다.

**읽는 사람은 출근 전 휴대폰으로 봅니다.** 맨 위 '오늘 결재할 것' 세 줄만 읽고도 할 일을 알 수 있어야 합니다.

1. **숫자 계산**
   `pip install -q -r requirements.txt && python -m aisec.paper update && python -m aisec.cli`
   - 종료코드 2면 데이터를 못 받은 것입니다. 회의를 열지 말고 막힌 주소를 그대로
     `reports/<날짜>.md` 에 "오늘은 휴업: 데이터 없음"으로 기록하고 끝냅니다. **추정치로 대신하지 마세요.**
   - screen.json 의 market.regime 이 '판정불가'이거나 failures 에 kospi 가 있으면 한 번 더 실행합니다(KRX 접속이 가끔 한 번 실패합니다).
   - picks 가 비어 있고 보유 종목도 없으면 "오늘 성립한 셋업 없음 — 쉬는 것도 매매"로 짧게 기록하고 끝냅니다.
   - 코드가 만드는 것: `data/<날짜>/` 에 screen.json · plans.json · holdings.md · dossier_<코드>.md(회의 후보 **와 보유 종목**) ·
     **brief_draft.md(결재 문서 초안)**.

2. **AI 부서 호출 (모두 한 번에 병렬, 백그라운드)**
   - market-desk: 하루 1번.
   - 리스크 '통과' 후보(추천 1순위는 반드시)마다: analysis-desk, news-desk, redteam-desk.
   - 보유 종목(config portfolio)마다: analysis-desk, news-desk, redteam-desk — `dossier_<코드>.md` 와 holdings.md 를 읽게 합니다.
   - 후보가 전부 차단이면: 대기 목록 1순위와 모의투자 대기·보유 건을 analysis-desk 1회로 묶어 봅니다.
   - 부탁할 때는 **파일 경로와 종목 코드, 물을 것만** 적습니다. 숫자를 부탁 글에 옮겨 적지 마세요(옮기다 틀립니다).
     부서는 자료 묶음에서 직접 읽습니다. 지난 의견이 필요하면 `reports/<지난 날짜>.md` 경로를 줍니다.

3. **부서 회의** (종목별)
   - 리스크 판정이 "차단"이면 결론은 무조건 **거절**. AI 의견으로 뒤집지 못합니다.
   - 보유 종목의 규칙 제안(전량 매도·익절·축소)도 AI 의견으로 바꾸지 않습니다. 부서는 근거 확인과 실행 방법만 말합니다.
   - 코드가 screen.json market.fit 에서 '피할 셋업'(지금 국면 평균 0% 이하)으로 분류한 셋업이면 한 단계 낮춥니다(승인→보류).
     '우위 미미'(0~+0.3%)는 낮추지는 않되 카드에 그대로 적습니다. 숫자 없는 '피할 셋업'은 낮추는 근거가 되지 않습니다.
   - 급변 규칙이 풀린 첫날의 신규 진입은 보류를 기본으로 합니다(2026-11 급락장에서 해제가 하루 만에 뒤집힌 일이 세 번 있었습니다).
   - 분석부가 "함정 의심"이거나, 반대편부의 질문에 아무 부서도 답하지 못하면 보류.
   - 의견이 갈린 지점에 이름을 붙입니다 (예: "종목은 강하다, 자리와 때는 아니다").
   - 보류를 제안할 때는 **재검토 조건을 숫자로** 적습니다. 다음 날 그 조건을 그대로 채점합니다.

4. **결재 문서** `reports/<날짜>.md`
   - `data/<날짜>/brief_draft.md` 를 `reports/<날짜>.md` 로 복사한 뒤, `[[…]]` 로 표시된 칸만 채웁니다.
     **숫자 칸은 고치지 않습니다.** 초안의 숫자가 이상해 보이면 문서를 고치지 말고 코드를 의심해 '데이터 한계'에 적습니다.
   - 채운 뒤 `python -m aisec.brief check reports/<날짜>.md` 로 안 채운 칸이 없는지 확인합니다.
   - 쓰는 법:
     - **오늘 결재할 것**: 3줄 이내, 급한 순서. 대표님이 할 행동을 동사로("HMM 50주를 장 시작에 전량 매도"). '(코드)' 요약 줄은 그대로 둡니다.
     - 부서 의견은 한 부서 한 줄. 결론과 확신도로 끝냅니다. 부서 보고를 통째로 붙이지 않습니다.
     - '확인 못함'은 데이터 한계에 **한 줄로 묶습니다**. 며칠째인지 적습니다. 절마다 되풀이하지 않습니다.
     - 어제 보류·거절·승인 제안이 있었으면 **어제 결정 돌아보기**에서 결과가 아니라 그날 알 수 있던 근거로 채점합니다. 놓친 기회도 적습니다.
     - 대표님 결재를 기다리는 안건은 `journal/agenda.md` 에 한 줄씩 쌓고, 문서에는 "결재 대기 안건 n건 → journal/agenda.md"로 가리킵니다.
       결재가 나면 그 줄을 지우고 결과를 매매 일지에 적습니다.
     - 전문용어를 처음 쓸 때는 괄호로 풉니다(앵커링, 오버행, 갭하락 등). 같은 것을 두 가지 말로 부르지 않습니다.
   - 마지막 줄은 초안에 들어 있습니다: "백테스트는 과거 성적일 뿐 미래 수익을 보장하지 않습니다. 최종 결정과 책임은 결재자에게 있습니다."

5. **모의투자 장부**
   - 대표님이 "<종목> 승인"이라고 하면 `python -m aisec.paper approve <브리핑 날짜> <종목코드>` 로 가상 매수를 등록합니다.
     리스크 '차단' 종목은 코드가 거부합니다. 실제 주문은 대표님이 신한 앱에서 직접 합니다(아직 자동 주문 없음).

6. **실전 매매 보고를 받으면** (`journal/real_trades.md`, `config.yaml` portfolio)
   - 매수 체결을 기록할 때는 같은 답장 안에서 **감시 손절(손절선 가격)을 걸었는지** 묻고 일지에 '걸었음/안 걸었음'을 적습니다.
     2026-11 HMM 거래에서 감시 손절을 걸지 않아 계획 손실의 두 배가 넘게 잃었습니다.

7. **작은 성공 체크**: MILESTONES.md 에서 오늘 새로 증거가 생긴 항목이 있으면 [x] 로 바꾸고 결재 문서 끝에 "오늘의 작은 성공"으로 적습니다.

8. **자가학습**: 매주 월요일에는 `python -m aisec.review` 도 실행해 `reports/review.md` 를 갱신하고,
   '리스크 판정별'·'셋업별' 표를 결재 문서 끝에 붙입니다. 같은 신호를 날마다 다시 세지 않은 '독립 신호' 숫자로만 말합니다.

9. 커밋: `git add reports data paper journal MILESTONES.md && git commit -m "brief: <날짜>"` 후 push.
